■ 주요 클래스
게임모드(GameMode) : 레벨에 하나만 존재하는 게임 규칙 정의 클래스
액터(Actor) : 월드에 배치할 수 있는 모든 오브젝트
폰(Pawn) : 플레이어 또는 컴퓨터가 조작할 수 있는 액터
캐릭터(Character) : 이동기능이 추가된 폰

■ 게임 모드
게임 규칙을 정의하는 클래스
레벨당 하나만 존재
우클릭 - 블루프린트 클래스 - game mode base

게임모드에 default pawn class가 있음. 우리가 만든걸로 넣기
전용 게임모드 지정 : window - world setting - game mode override - 내가 만든 게임모드 지정

■ 입력 시스템
언리얼 입력방식이 2가지였는데 이제 축 및 액션 매핑은 폐기됨. (기능 폐기는 아니고 새로 만드는건 안됨)

언리얼의 입력 시스템
• 입력 액션(Input Action) : 키보드, 마우스 등 입력 행동 정의
• 입력 매핑
• 입력 매핑 컨텍스트(Context) : 액션과 매핑을 묶어주는 역할
우클릭 - input - input action (IA_Move 이름 짓기)
bool은 키가 눌렸나, 안 눌렸나 판단. Axis는 축임.

매핑 컨텍스트는 추가하고 지우고 여러개도 할 수 있음.

input - input mapping context (IMC_DefaultInput )
매핑 + 누르고 만든 입력 액션 넣음
사용할 키를 배열에 넣어줌 (그리고 펼치기)
trigger : 어떤 방식으로 입력을 받아들일지 (기본적인건 none)
modify : 이 값이 어떻게 들어올 것인지

wasd
w:그대로 (기본이 x축 +임)
s : Negate(x,y,z)
d,a는 스위즐 입력 축값 a는 negate 추가(x,y,z)

보통 입력은 플레이어 컨트롤로 사용함.
BP_MyCharacter의 이벤트 그래프에서 Get Player Controller로 얻을 수 있다. return value로 끌어다가 Enhanced Input Local Player SubSystem 생성. 또 이어서 끌어다가 add mapping context 함수 만들고, event beginplay에 연결

IA_move를 enhanced로 꺼내면 키가 눌렸으면 얘가 반환된다. 트리거 노드다.
Action Value에 Break Vector 2D

• Subsystem : 반 매니저 급. 얘를 통해서 너가 내부코드 수정할 수 있게 해줄게. Input Local Player 접근

레벨 시작되면 GameMode 기준으로 가장 먼저 초기화된다.
멀티게임 하면 서버에만 존재함.

■ 캐릭터
폰에서 캐릭터 무브먼트 컴포넌트가 추가된 것 (하지만 폰에서 캐릭터 무브먼트 컴포넌트를 이용 못함)
언리얼에서 캐릭터 세팅 안하면 기본 폰으로 세팅함

언리얼 기본 이동속도는 600이다
변수의 인스턴스 변경 가능을 키면 레벨에서 수정 가능 (변수 옆 눈알 표시)
변수에 스폰시 노출을 키면 SpawnActor함수에서 변수를 바로 바꿀 수 있다.
