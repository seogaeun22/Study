■ Tick

모든 게임과 게임 엔진은 게임 루프를 사용하여 작동한다.
(지속적으로 실행되고 게임을 업데이트하는 루프)

1. Get input : 게임 또는 게임 엔진은 플레이어로부터 입력을 받는다. (키보드, 마우스, 컨트롤러)

2. Update game state : 입력이 처리되면 엔진이나 게임에서 게임 상태를 업데이트 한다.
(변수 설정, 함수 호출, 게임 이벤트 일어나게 함, 게임에서 그래픽을 이미지로 화면에 렌더링 함)

이것을 반복함.

Frame : 게임 루프의 각 사이클
컴퓨터나 CPU는 가능한 빨리 루프를 실행하려고 한다.
따라서 경우에 따라 초당 수백 번씩 게임 루프를 실행할 수도 있다.

FPS : 초당 프레임 수 (1초당 프레임 수). CPU 속도에 따라 달라질 수 있다.

Tick() : 게임의 모든 프레임에서 호출되는 특별한 기능. 각 프레임에서 틱 호출됨. FPS에 따라서 초당 최대 6070회까지 반복해서 수행됨.

틱은 캐릭터가 삭제되거나 게임이 종료될 때까지 또는 액터가 삭제될 때까지 계속 호출된다.

프레임마다 호출됨.

■ Delta Time

Deltatime 변수를 사용하여 게임 프레임 속도를 독립적으로 만들 수 있다.

이전의 움직이는 발판 문제 = 속도 문제
컴퓨터마다 게임 실행 속도가 다르다. 빠른 컴퓨터는 100FPS, 느린 컴퓨터는 30FPS 실행할 수 있음. Tick 함수 내에서 값을 더하거나 빼는 경우 문제가 발생할 수 있다. 다른 컴퓨터에서 어떤놈은 1초에 100cm 어떤놈은 1초에 30cm 움직인다.

이를 해결하게 위해 DeltaTime이라는 특수 변수를 사용한다.

Delta Time : CPU가 게임의 마지막 프레임을 계산하는 데 걸린 시간

게임 루프
1. Get input
2. Update game state
3. Render graphics to the screen
이 모든 작업을 수행하는 것은 본질적으로 게임의 한 프레임을 계산하는 것이다. 마지막 프레임에 대해 이를 계산하는 데 걸리는 시간(초)를 델타 시간이라고 한다.

따라서 틱 내부에 이와 같은 연산이 있을 때마다 추가하는 값에 델타 시간을 곱하여 코드 프레임 속도를 독립적으로 만들면 프레임 속도에 관계없이 코드가 동일하게 실행된다.

Tick(float DeltaTime)
{ CurrentLocation.X = CurrentLocation.X + (1*DeltaTime); }
언리얼 자체에서 입력으로 제공되는 함수의 인자로 들어감.

빠른 컴퓨터 : 델타 시간이 짧아짐. 100FPS면 delta time은 0.01초
느린 컴퓨터 : 델타 시간이 길어짐. 10FPS면 delta time은 0.1초

빠컴 : 1초에 100cm움직임. => 100에 0.01을 곱하면 1cm
느컴 : 1초에 10cm 움직임. => 10에 0.1을 곱하면 1cm

두 방정식에 각각의 델타 시간을 곱하면 같은 숫자가 나온다.

명심해야 할 점 : Delta Time을 사용하기 시작하자마자 수치가 급격히 감소한다. (빠컴의 경우 100cm -> 1cm이 됨)

따라서 1초에 몇 cm를 움직이고 싶은지 생각하고 그에 따라 값을 변경해야 한다. (100*DeltaTime 하면 1초에 100cm 움직임)
