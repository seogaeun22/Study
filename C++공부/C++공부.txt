■ 벡터 (vector)
임의의 위치에 있는 원소 접근 O(1)
임의의 위치에 원소 추가/제거 : O(n)
	그 뒤에 오는 원소들을 한 칸 씩 이동시켜 줘야함. (n번의 복사 필요)
맨 뒤 새로운 원소 추가/제거 : amortized O(1)
	할당된 공간을 다 채웠을 때 새로운 큰 공간을 다시 할당하고, 기존의 원소들을 복사함.

[] 또는 at으로 임의의 원소 접근
맨 뒤 원소 추가 : push_back
맨 뒤 원소 제거 : pop_back

▶ 반복자 타입: RandomAccessIterator
RandomAccessIterator는 BidirectionalIterator를 상속받고 있다.

■ 반복자 (iterator)
컨테이너의 원소에 접근할 수 있는 포인터와 같은 객체
컨테이너에 iterator 멤버 타입으로 정의 됨

▶ begin() : 첫번째 원소를 가리키는 반복자 리턴
▶ end() : 마지막 원소 한 칸 뒤를 가리키는 반복자 리턴
	빈 벡터를 표현하기 위해 마지막 원소의 뒤를 가리키는 반복자를 리턴함.
	begin() == end() 라면 원소가 없는 벡터를 의미함.

▶ std::vector<int>::iterator itr = vec.begin();
*itr 로 itr이 가리키는 원소를 볼 수 있다.
	(*연산자 오버로딩해서 포인터 처럼 동작하게 만듦)
	(*연산자는 itr이 가리키는 원소의 레퍼런스를 리턴한다.)

vector 에서 반복자로 erase 나 insert 함수 : O(n)
vec.erase(vec.begin() + 3);	//vec[3] 제거
vec.insert(vec.begin()+2, 15);	//vec[2] 앞에 15 추가

컨테이너에 원소를 추가하거나 제거하게 되면 기존에 사용하였던 모든 반복자들을 사용할 수 없게 된다.

size_type은 vec.size()의 반환타입과 같다. 원소 개수와 인덱스를 표현하기 위해 제공되는 타입 별칭이다.

for (std::vector<int>::size_type i = 0; i != vec.size(); i++) {
if (vec[i] == 20) {
vec.erase(vec.begin() + i);
i--;
}
}

▶ std::erase(vec,20); 으로 값이 20인 원소를 전부 삭제 가능하다. (c++20)

▶ const_iterator : 가리키고 있는 원소의 값을 바꿀 수 없다.
std::vector<int>::const_iterator citr = vec.cbegin() + 2;
*citr = 30; 		// 불가능

cbegin() 과 cend() 함수를 이용해서 얻을 수 있다.
반복자의 값을 바꾸지 않고 참조만 하는 경우가 많으므로 const_iterator를 적절히 이용해라

▶ 역반복자
std::vector<int>::reverse_iterator r_iter = vec.rbegin();
for(; r_iter != vec.rend(); ++r_iter)
 std::cout << *r_iter << std::endl;

rend() : 맨 앞 원소의 바로 앞을 가리킴
rbegin() : 마지막 원소를 가리킴
역반복자는 값이 증가하면 앞쪽 원소로 가게 된다.

▶ 상수 역반복자
const_reverse_iterator
crbegin() 과 crend()로 얻을 수 있다.

size_type의 경우 부호 없는 정수 타입이기에 i--를 하면 -1이 되는 것이 아니라 해당 타입에서 가장 큰 정수가 되버린다. 보훙있는 정수를 선언해야하는데 이 경우 vector의 index 타입과 일치핳지 않아서 타입 캐스팅을 해야한다.
=> 역으로 원소를 참조하고 싶다면 역반복자를 사용해라

■ 범위 기반 for 문 (range based for loop)
C++11 부터 사용 가능

for (원소를 받는 변수 정의 : 컨테이너 ) {}

for(int elem : vec)
	std::cout << elem << std::endl;
==> 매 루프마다 vec의 원소들이 elemp에 '복사'돼서 들어감

for(const auto& elem : vec)
	std::cout << elem << std::endl;
==> 상수레퍼런스로 접근함.

■ 리스트(list)
양방향 연결 구조를 가진 자료형
▶ 임의의 위치에 접근을 바로 할 수 없다.
list 컨테이너 자체에서는 시작 원소와 마지막 원소의 위치만을 기억하기 때문에, 임의의 위치에 있는 원소에 접근하기 위해서는 하나씩 링크를 따라가야 한다.
- [] , at 함수가 아예 정의되어 있지 않다.

임의의 위치에 원소를 추가하거나 제거하는 작업 O(1)
	벡터의 경우 O(n)이었다.
	리스트는 원하는 위치 앞과 뒤에 있는 링크 값만 바꿔주면 된다.

std::list<int> list;
itr++과 itr--만 사용 가능하다.(전위도 가능)
itr+5는 불가능하다. (임의의 위치에 있는 원소를 가리킬 수 없다.)

반복자는 한 칸씩 움직일 수밖에 없다.
==> 메모리 상에서 원소들이 연속적으로 존재하지 않을 수 있기에
	벡터의 경우 메모리 상에서 연속적으로 존재하기 때문에 쉽게 임의의 위치에 있는 원소를 참조할 수 있다.

▶ 반복자 타입: BidirectionalIterator

lst.erase(itr); 가능. 벡터와는 다르게 원소를 지워도 반복자가 무효화 되지 않는다. (각 원소들의 주소값들은 바뀌지 않기 때문. 벡터는 노드 이동함)

■ 덱 (deque - double ended queue)
임의의 위치의 원소에 접근 : O(1) (벡터와 같음)
맨 뒤에 원소를 추가/제거 : O(1) (벡터와 같음)
맨 앞에 원소를 추가/제거 : O(1)
임의의 위치의 원소를 추가/제거 : O(n) (벡터도 O(n)이지만 덱이 더 빠름)

▶ 벡터와 다른점
원소들이 실제로 메모리 상에서 연속적으로 존재하지 않는다.
이 때문에 원소들이 어디에 저장되어 있는지에 대한 정보를 보관하기 위해 추가적인 메모리가 더 필요로 한다.

실행속도를 위해 메모리를 많이 희생하는 컨테이너

▶ 덱 구조
- 원소들이 일정 크기로 잘려서 각각의 블록 속에 존재한다.
- 따라서 이 블록들이 메모리 상에 어느 곳에 위치하여 있는지 저장하기 위해서 각각의 블록들의 주소를 저장하는 벡터가 필요하다.

※ 참고로 이 벡터는 기존의 벡터와 다르게 새로 할당 시에 앞쪽 및 뒤쪽 모두 공간을 남겨 놓게 된다. (벡터의 경우 뒤쪽에만 공간이 남았다.)

1. 각각의 블록은 일정한 크기를 가지는 배열로 볼 수 있다.
2. 각각의 블록들을 가리키는 포인터들의 벡터가 있다.


▶ 벡터보다 임의의 위치의 원소를 추가/제거가 빠른 이유
기존의 원소들을 복사하는 벡터와 달리 단순히 새로운 블록을 만들어서 뒤에 추가되는 원소를 넣어주면 된다.

(물론 덱의 경우 블록 주소를 보관하는 벡터가 꽉 차게 되면 새로운 공간에 모두 복사해야 한다.)
하지만 블록 주소의 개수는 전체 원소 개수보다 적고, 대체로 벡터에 저장되는 객체들의 크기가 주소값의 크기보다 크기 때문에 덱의 복사 속도가 벡터보다 훨씬 빠르다.

▶ Random Access Iterator
임의의 위치로 O(1) 이동 가능
블록 내부의 연속성과 블록 위치를 즉시 계산할 수 있는 인덱스 구조가 결합되어 Random Access Iterator를 제공함.
블록 번호 = (시작 위치 + i) / 블록 크기
블록 내부 위치 = (시작 위치 + i) % 블록 크기

덱은 빈틈없는 인덱스 구조를 제공해야하기에 삭제시에 땡겨줘야함. (더 가까운 끝을 선택하여 이동함)
덱의 블록당 수용량은 deque<T>에서 T의 크기와 표준 라이브러리 구현에 따라 정해진다.

■ 작업별 컨테이너 사용
- 일반적인 상황 : 벡터
- 중간에 원소들을 추가/제거 하는 일이 많고, 원소들을 순차적으로만 접근 : 리스트
- 맨 처음과 맨 끝 모두 원소들을 추가하는 작업을 많이한다 : 덱
O(1) 작동은 이론적인 결과고 실제 프로그램은 nn의 크기에 따라서 O(logN)이나 O(N)보다 느릴 수 있다.
속도가 중요한 환경이라면 적절한 벤치마크를 통해 성능을 가늠하자.

■ 연관 컨테이너(associative container)
▶ 키(key) - 값(value) 구조
템플릿 라이브러리이기 때문에 키와 값 모두 임의의 타입의 객체가 될 수 있다.

▶ 셋(set) : 특정 키가 연관 컨테이너에 존재하는지 유무
	셋, 멀티셋
▶ 맵(map) : 특정 키에 대응되는 값이 무엇인지 질의
	맵과 멀티맵을 셋처럼 사용할 수 있다.
	맵의 경우 셋보다 사용하는 메모리가 크기 때문에 키의 존재 유무만 궁금하면 셋을 사용하자.

■ 셋(set)
std::set<T> s;

insert : 셋에 원소를 추가 (예: s.insert(10);)
	시퀀스 컨테이너와 다르게 어디에 추가할지에 대한 정보가 없다.
	- 시퀀스 컨테이너 : 상자 하나에 원소 한 개씩 담고, 각 상자에 번호를 매김
	- 연관 컨테이너 : 그냥 큰 상자 하나에 모든 원소를 쑤셔 넣음.
	그 상자 안에 원소가 어디에 있는지 중요X, 원소가 "있냐/없냐" 중요O

셋에 원소를 추가하거나 지우는 작업 : O(logN)
	- 시퀀스 컨테이너의 경우 임의의 원소를 지우는 작업이 O(N)이므로 셋이 더 빠름

※ 시퀀스 컨테이너가 임의의 원소를 지우는 작업이 O(N)인 이유
vector : 	값 탐색 = O(N) + 중간 삭제 O(N) = O(2N) = O(N)
list : 		값 탐색 = O(N) + 중간 삭제 O(1) = O(N)
deque : 	값 탐색 = O(N) + 중간 삭제 O(N) = O(2N) = O(N)

▶ 셋은 BidirectionalIterator
임의의 위치에 있는 원소 접근이 불가능. 순차적 하나씩 접근

▶정렬된 상태를 유지한다.
원소 추가하는 작업 : O(logN)
	시퀀스 컨테이너와 다르게 원소를 순서를 지키며 넣기에 O(logN)이 걸린다.

셋은 보통 균형 이진 탐색 트리로 구현된다.
탐색 범위를 대략 절반씩 줄여가며 들어갈 위치를 찾기에 logN이 된다.

find() : 못 찾으면 end()리턴, 찾으면 해당 원소를 가리키는 iterator 반환 O(logN)
	균형이진탐색트리라 찾는데 O(logN)걸린다.

▶ std::find()와 set::find()의 차이점
std::find()는 컨테이너 내부 구조를 모르고 처음부터 iterator 하나씩 넘겨가며 찾는 범용 알고리즘 O(N)
set::find()는 "난 트리 구조니까 내 구조를 이용해서 빠르게 찾아줄게"라는 set 전용 기능 O(logN)

▶ 셋은 중복된 원소들이 없다.
	중복된 원소를 허락하고 싶다면 멀티셋(multiset)을 사용하면 된다.

시퀀스 컨테이너들과 마찬가지로 셋은 범위 기반 for문을 지원한다.

▶ 정렬을 하기 위해 비교 수행을 위한 operator< 연산자 만들기
bool operator<(const T& t) const {}
const 타입을 레퍼런스로 받는 const 함수로 만들어야 한다.

셋은 내부적으로 정렬 시에 상수 반복자를 사용하기에 <를 사용하기 위해 const 함수로 만들어야 한다.
(상수 반복자는 상수 함수만을 호출할 수 있다.)

셋 내부에서 두 개의 원소가 같냐 다르냐를 판별하기 위해 ==를 사용하지 안흔ㄴ다.
두 원소 A 와 B가 셋 내부에서 같다는 의미는 A.operator<(B)와 B.operator<(A) 모두 false 라는 뜻이다. (둘다 false면 a==b라고 생각한다.)

operator를 설계할 때 반드시 다른 객체는 operator<상에서도 구분될 수 있도록 만들어야 한다.
A<B와 B<A 둘 중에 하나는 반드시 True여야 한다.

• A<A는 거짓
• A<B != B<A
• A<B 이고 B<C 이면 A<C
• A==B이면 A<B와 B<A 둘 다 거짓
• A==B이고 B==C이면 A==C
위 조건을 만족하는 < 연산자를 strict weak ordering을 만족한다고 한다.

▶ strict weak ordering : 원소들의 순서를 일관되게 정할 수 있도록 비교 함수가 지켜야 하는 규칙

위 조건 중 하나라도 맞지 않으면 컴파일타임에 오류가 발생하지 않고, 런타임 상에서 오류가 발생할텐데 디버깅이 꽤나 까다로울 것이다.

또는 bool operator() (const T& t1, const T& t2) { return t1 > t2; } 식으로도 만들 수 있다.
(실제 set 클래스의 두 번째 인자로 Compare를 받기에. Compare타입을 전달하지 않으면 key클래스의 operator<로 비교를 수행한다.)

std::set<Todo, TodoCmp> todos;
todos.insert(Todo(1,"농구하기"));

=> 셋은 원소의 삽입/삭제/탐색을 O(logN)에 수행하는 자료구조다.

■ 맵(map)
셋과 비슷하지만 키에 대응하는 값(value)까지도 같이 보관하는 자료구조

▶ 맵의 경우 템플릿 인자로 2개를 가진다.
1. 키의 타입
2. 값의 타입
std::map<std::string, double> m;

▶ 맵의 insert 함수는 pair 객체를 인자로 받는다.
m.insert(std::pair<std::string, double> ("서가은", 24));

template <class T1, class T2>
struct std::pair {
T1 first;
T2 second; } 가 std::fair 객체다.

▶ 타입을 지정하지 않아도 std::make_pair 함수로 std::pair 객체를 만들 수도 있다.
m.insert(std::make_pair("서가은", 24));

▶ 혹은 insert를 안 쓰더라도 [ ]로 바로 원소를 추가할 수 있다.
m["서가은"] = 24;
만일 키가 이미 존재하고 있다면 값이 대체될 것이다.

template <typename K, typename V>
void print_map(std::map<K,V>& m)
{
	for(auto itr = m.begin(); itr != m.end(); ++itr)
		std::cout << itr->first << " " << itr->second << std::endl;
}
셋의 경우 *itr 가 지정된 원소를 바로 가리켰는데, 맵의 경우 반복자가 맵에 저장되어 있는 std::pair 객체를 가리키게 된다. 따라서 itr->first 는 해당 원소의 키를, itr->second는 해당 원소의 값을 알 수 있다.

범위 기반 for 문의 경우
for(const auto& kv : m)
	cout << kv.first << " " << kv.second << endl;

▶ 맵에 저장된 값을 찾고 싶다면 [ ]연산자를 이용하면 된다.
[ ] 연산자는 인자로 키를 받아서 이를 맵에서 찾아서 대응 되는 값을 돌려준다.

<주의할점>
없는 키를 참조하면 자동으로 값의 디폴트 생성자를 호출해서 원소를 추가해버린다.
m["서똥개"] 출력하면 0 나옴
따라서 되도록이면 find 함수로 원소의 키가 존재하는지 먼저 확인 후, 값을 참조하는 것이 좋다.
auto itr = m.find(key);
if ( itr != m.end() ) cout << itr->first << " " << itr->second << endl;

▶ 맵도 중복된 원소를 허락하지 않는다.
이미 같은 키가 원소로 들어 있다면 나중에 오는 insert는 무시된다.

■ 멀티셋(multiset) 과 멀티맵(multimap)
멀티셋과 멀티맵은 중복된 원소를 허락한다.

std::multiset<std::string> s;
std::multimap<int, std::string> m;

▶멀티맵의 경우 [ ] 연산자를 사용할 수 없다.
한 개의 키에 여러개의 값이 대응될 수 있기 때문이다.
1, hello
1, hi
에서 hello를 리턴할지, hi를 리턴할 지 알 수 없기 때문이다.

m.find(1)->second;
find했을 때 해당하는 키가 없다면 m.end()를 리턴한다. 1이라는 키에 여러 값이 대응되어있으면 해당 값 중 아무거나 리턴한다.

▶ equal_range()
인자로 멀티맵의 키를 받은 뒤에, 이 키에 대응되는 원소들의 반복자들 중에서 시작과 끝 바로 다음을 가리키는 반복자를 std::pair 객체로 만들어서 리턴한다.
즉, begin()과 end()를 std::pair로 만들어서 세트로 리턴한다. (first: 시작점, second: 끝점 바로 뒤)

auto range = m.equal_range(1);
for(auto itr = range.first; itr != range.second; ++itr)
	std::cout << itr->first << " : " << itr->second << " " << std::endl;

■ 정렬되지 않은 셋과 맵 (unordered_set, unordered_map)
C++11에 나온 컨테이너 (지금까지 컨테이너는 C++98에 추가됨)

원소들이 순서대로 정렬되어 들어가지 않는다. 반복자로 원소들을 하나씩 출력하면 거의 랜덤한 순서로 나온다.

▶ insert, erase, find 모두 O(1)로 수행된다.
셋이나 맵의 경우 O(logN)이었다.

■ 해시 함수(Hash function)
unordered_set과 unordered_map은 원소를 삽입하거나 검색 하기 위해 먼저 해시 함수를 사용한다.

▶ 해시 함수
임의의 크기의 데이터를 고정된 크기의 데이터로 대응시켜주는 함수
(대게 고정된 크기의 데이터 : 일정 범위의 정수값)

해시함수는 1부터 D(상자의 수)까지 값을 반환하고 그 해시값(해시 함수로 계산할 값)을 원소를 저장할 상자의 번호로 삼게 된다. 해시 함수는 구조 상 최대한 1부터 D까지 고른 값으로 반환하도록 설계되어있다. 따라서 모든 상자를 고루고루 사용 할 수 있게 된다.

▶ 같은 원소를 해시 함수에 전달한다면 같은 해시값을 리턴한다.
이 덕분에 원소의 탐색이 빠르게 수행된다.

▶ 해시 함수가 해시값 계산을 O(1)에 처리한다.
따라서 unordered_set과 unordered_map 모두 탐색을 O(1)에 처리할 수 있다.

▶ 해시 충돌(hash collision)
다른 원소임에도 불구하고 같은 해시값을 갖는 경우

▶ 상자의 수도 충분히 많아야 상수시간 O(1) 탐색을 보장할 수 있다.
운이 매우 나빠서 모든 원소가 상자1에 들어가면 탐색이 O(N)으로 실행될 것이다.
=> unordered_set과 unordered_map의 경우 평균적으로 O(1)로 원소 삽입/탐색 수행하지만
	최악의 경우 O(N)으로 수행될 수 있다.
(그냥 set과 map의 경우 평균과 최악 모두 O(logN)이다.)

보통 안전하게 set, map 사용하고, 최적화가 필요한 작업일 경우 해시 함수를 잘 설계해서 unordered_set과 unordered_map을 사용하는 것이 좋다. (기본 타입의 경우 라이브러리 자체적으로 해시함수가 내장되어 있으므로 그냥 사용하면 된다.)

▶ rehash
처음부터 많은 개수의 상자를 사용할 수 없기 때문에 (메모리 낭비)
상자의 개수는 삽입되는 원소가 많아짐에 따라 점진적으로 늘어나게 된다. 문제는 상자의 개수가 늘어나면 해시 함수를 바꿔야 하기 때문에 (더 많은 값들을 해시값으로 반환할 수 있도록) 모든 원소들을 처음부터 끝까지 다시 insert 해야한다.
이를 rehash라 하며 O(N)만큼 시간이 걸린다.

------------------- 추가 해시 설명 ---------------------------
■ 해시함수, 해시충돌이 뭔지
해시 함수 : 입력받은 key를 일정한 규칙에 따라 해시값으로 변환하는 함수
해시 테이블 : 해시 값을 이용해 원소를 저장하고 검색하는 자료구조
해시 충돌 : 서로 다른 키가 동일한 상자에 배정되는 현상
해시충돌 자체가 오류는 아니다.

상자 위치는 O(1)에 알아냈지만, 상자 내부에서 원하는 원소를 찾는 작업이 O(N)이 되어버림. (모든 원소가 한 상자에 몰림)

■ 충돌 해결 방식 2가지
▶ 1. 체이닝
같은 상자에 들어오는 원소들을 연결해서 관리하는 방법
장점 : 구현 원리가 비교적 간단하고 충돌이 발생해도 원소를 저장할 수 있다.
단점 : 충돌이 많아지면 한 버킷을 순차적으로 탐색해야 하므로 느려짐

C++ 표준 unordered_map과 unordered_set은 버킷 기반 구조를 사용하며, 체이닝 방식으로 구현하는 것이 일반적이다.

▶ 2. 개방 주소법
충돌이 발생하면 다른 빈 상자를 찾아서 저장하는 방식
선형 탐사, 이차 탐사, 이중 해싱 등 여러 종류가 있다.

다음 위치 찾는 방법 (빈공간)
선형 탐사 - 한 칸씩 이동
이차 탐사 - 제곱 형태의 간격으로 이동
이중 해싱 - 두번째 해시 함수로 이동 간격 결정

장점 : 별도 연결 노드 없이 배열 내부에 저장할 수 있어 캐시 효율이 좋을 수 있다.
단점 : 빈 공간을 찾는 과정이 길어질 수 있고 삭제 처리도 까다롭다.
개방 주소법이 무조건 빠른건 X. 상황에 따라 다름.

문제 : 버킷이 거의 가득 차면 빈 공간을 찾기 위해 여러 버킷을 검사해야함.
특히 선형 탐사는 원소들이 뭉치는 클러스터링(Clustering) 현상이 발생할 수 있다.
최악 O(N)

■ 해시 충돌 예방
일반적인 해시 테이블에서 충돌을 완전히 없애기는 어렵다.
충돌 최소화를 하자.
- 좋은 해시 함수 사용 : 입력값들이 여러 버킷에 골고루 분포하도록 만들어야함.
- 버킷 수 늘리기 : 버킷이 5개보다 100개인게 원소들이 분산될 공간이 많아짐 (메모리 사용량 증가)
- 부하율 관리 : 부하율은 (원소 수/ 버킷 수) C++에서 현재 부하율 확인과 최대 부하율을 설정 조회, 버킷 확보, 버킷 수 재조정 함수를 제공함.

■ rehashing(리해싱) : 원소가 증가해서 부하율이 너무 높아지면 해시 테이블은 버킷 수를 늘리고 원소들을 다시 배치할 수 있다.
단, 버킷을 늘려도 모든 충돌이 사라지는 건 아니다.

해시 테이블의 핵심은 원소를 정렬해서 저장하는 것이 아니라, 원소의 키를 이용해 저장할 위치를 빠르게 결정하는 것이다.

▶ find 함수
unordered_set과 unordered_map 모두 find 함수를 지원하며 사용법은 그냥 셋과 동일하다.
해당 원소 존재 : 원소를 가리키는 반복자 리턴
해당 원소 없음 : end() 리턴

▶ erase
원소 제거하고 싶으면 find 함수로 원소를 가리키는 반복자를 찾은 뒤에 전달하면 된다.
s.erase(s.find("hi"));

■ 내가 만든 클래스를 unordered_set/unordered_map의 원소로 넣고 싶을 때
셋과 맵보다 어렵다.
내 클래스 객체를 위한 '해시 함수'를 직접 만들어줘야 한다.
셋/맵과 달리 정렬은 필요하지 않아서 operator<는 필요하지 않지만,
해시 충돌 발생 시에 상자 안에 있는 원소들과 비교를 해야하기에 operator==는 필요하다.

C++에서 기본적인 타입들에 대한 해시 함수들을 제공하고 있다.
해시 함수를 직접 제작하는 일은 꽤나 어렵다.
unordered_set이나 unordered_map이 제대로 된 성능을 발휘하기 위해 해시 함수가 입력받은 키를 잘 흝뿌려야 한다.

■ 연관 컨테이너 정리
데이터 존재 유무만 궁금 → set
중복 데이터를 허락 → multiset (insert, erase, find 모두 O(logN)이고 최악도 O(logN)이다.
데이터에 대응되는 데이터를 저장하고 싶은 경우 → map
중복 키를 허락 → multimap(inser, erase, find 모두 O(longN)이고 최악도 O(logN)이다.
속도가 매우매우 중요해서 최적화를 해야하는 경우 → unordered_set, unordered_map (insert, erase, find 모두 O(1), 최악의 경우 O(N)이라 해시함수와 상자 개수를 잘 설정해야 한다.)

♥ C++ 표준 알고리즘 라이브러리 ♥

■ 알고리즘(algorithm)
컨테이너의 반복자들을 가지고 이런 저런 작업을 쉽게 수행할 수 있도록 도와주는 라이브러리
알고리즘 함수들은 크게 2가지 형태를 지닌다.
1. template <typename Iter> void do_something(Iter begin, Iter end);
2. template <typenmae Iter, typename Pred> void do_something(Iter begin, Iter end, Pred pred)

1은 알고리즘을 수행할 반복자의 시작점과 끝 점 바로 뒤를 받는다.
2는 반복자는 동일하게 받되, 특정한 조건을 추가 인자로 받게 된다.

특정한 조건 = 서술자(Predicate)
Pred에는 보통 bool을 리턴하는 함수 객체(Functor)를 전달하게 된다.

■ 정렬(sort, stable_sort, partial_sort)
정렬 알고리즘에서 3가지 종류의 함수를 지원한다.

• sort : 일반적인 정렬 함수
• stable_sort : 정렬을 하되 원소들 간의 순서를 보존. sort보다 좀 더 느리다.
벡터에 [a,b] 순으로 있었는데, a와 b의 크기가 같다면 정렬을 [a,b] 또는 [b,a]로 할 수 있다. sort는 순서를 랜덤으로 정하지만, stable_sort는 반드시 그 순서를 보존하여 [a,b] 순으로 나온다.
• partial_sort : 배열의 일부분만 정렬

■ sort 함수
정렬할 원소의 시작 위치와, 마지막 위치 바로 뒤를 반복자로 받는다.

std::sort(vec.begin(), vec.end());

▶ sort에 들어가는 반복자의 경우 반드시 임의접근 반복자(RandomAccessIterator) 타입을 만족해야한다.
벡터와 덱만 가능하다. (리스트는 양방향 반복자(BidirectionalIterator)라 안됨.)

• 기본적으로 오름차순 정렬
내림차순으로 정렬하고 싶다면 3번째 인자로 특정한 조건을 전달하면 된다.

함수 객체
struct int_compare
{
	bool operator() (const int& a, const int& b) const { return a > b; }
};

std::sort(vec.begin(), vec.end(), int_compare());

▶ greater
• functional 헤더에 다음과 같은 템플릿 클래스가 존재해서 따로 int 형, string 형을 만들 필요가 없다.

template<typename T>
struct greater { bool operator() (const T& a, const T& b) const {return a > b;}

std::sort(vec.begin(), vec.end(), greater<int>());

• greater에 우리가 사용하고자 하는 타입을 넣게 되면 위와 같은 함수 객체를 자동으로 만들어준다.
(물론 그 해당하는 타입의 > 연산자가 존재해야한다. int는 기본 타입이기에 당연히 존재한다.)

■ partial_sort 함수
일부만 정렬하는 함수
인자를 기본 3개 받는다.
▶ std::partial_sort(start, middle, end)

• 정렬을 [start, end) 전체 원소들 중에서 [start, middle) 까지 원소들이 전체 원소들 중에서 제일 작은애들 순으로 정렬시킨다.

std::partial_sort(vec.begin(), vec.begin() + 3, vec.end());
벡터 전체 원소들 중에서 가장 작은 3개 원소만 정렬되고 나머지 원소들은 랜덤하게 남아있게 된다.

• O(NlogM)
N: 전체 원소의 개수
M: 정렬하려는 부분의 크기

상위 10명 학생의 성적만 보고 싶을 때 부분정렬을 활용하면 빠르다.

■ stable_sort 함수
원소가 삽입되어 있는 순서를 보존하는 정렬 방식

sort 함수의 경우 정렬 과정에서 원소들 간의 상대적 위치를 랜덤하게 바꿔버리지만
stable_sort의 경우 그 순서를 처음에 넣었던 상태 그대로 유지한다.
이러한 제약 조건 때문에 stable_sort는 그냥 sort 보다 좀 더 오래걸린다.

sort 함수 : 최악의 경우 O(NlogN)이 보장됨.
stable_sort 함수 : 최악의 경우 O(N(logN)²))로 작동됨.

■ 원소 제거 (remove, remove_if)
대부분의 컨테이너에서는 원소를 제거하는 함수를 지원하고 있다.
vec.erase(vec.begin() + 3); //vec[3] 제거

하지만 이 함수 하나로 많은 작업들을 처리하기 부족하다.
값이 3인 원소 제거하려면 반복자를 활용하는데, 원소가 제거될 때 마다 기존에 제거하였던 반복자들이 초기화 되기에 해당 위치를 가리키는 반복자를 다시 가져와야 한다.

벡터의 erase 함수는 2가지 형태가 있다.
Iterator erase(Iterator pos);	//pos가 가리키는 원소를 벡터에서 지움
Iterator erase(Iterator firset, Iterator last);	//first부터 last 사이에 있는 모든 원소들을 지우는 형태
이 두 함수 모두 값이 3인 원소 제거를 수행하는데 부족함이 있다.

왼쪽에서 오른쪽으로 읽으면서 3을 찾는다. 찾으면 그 다음 원소부터 1칸 씩 shift한다.
3을 다시 발견하면 무시하고 그 다음 원소를 찾는다. 끝에 도달하면 종료하고 위치를 가리키는 반복자를 리턴한다.
따라서, 알고리즘이 끝나게 되면 해당하는 위치에서 전까지 3이 제외된 원소들로 채워지게 된다.

vec.erase(std::remove(vec.begin(), vec.end(), 3), vec.end());

▶ remove 함수는 원소의 이동만을 수행하지 실제로 원소를 삭제하는 연산을 수행하지 않는다.
▶ 벡터에서 실제로 원소를 지우기 위해서는 반드시 erase 함수를 호출하여 실제로 원소를 지워줘야만 한다.

▶ remove 함수의 반복자 타입은 ForwardIterator이다.
벡터뿐만이 아니라, 리스트, 셋, 맵 모두 사용 가능하다.

▶ remove_if : 특정한 조건을 만족하는 원소들을 제거

vec.erase(std::remove_if(vec.begin(), vec.end(), is_odd()), vec.end());
remove_if 함수는 세번째 인자로 조건을 설명할 함수 객체를 전달받는다.
함수 객체로 실제 함수를 전달할 수도 있다.
vec.erase(std::remove_if(vec.begin(), vec.end(), odd), vec.end());

• remove_if에 전달되는 함수 객체의 경우 이전의 호출에 의해 내부 상태가 달라지면 안된다.
함수 객체 안에 인스턴스 변수를 넣는 것은 원칙상 안된다.
• 해당 함수 객체가 여러번 복사 될 수 있기 떄문이다.
함수 객체에는 절대로 특정 상태를 저장해서 이에 따라 결과가 달라지는 루틴을 짜면 안된다. (함수 객체의 복사 생성된 버전을 받음)
외부 변수로 빼는 방법이 있지만 STL을 사용할 때마다 외부에 클래스나 함수를 하나씩 만들어줘야함.

==> STL 알고리즘을 사용할 때 그 안에 직접 써놓자.

■ C++20부터 std::erase()와 std::erase_if()
특정값 삭제 - std::erase(vec, 3);
조건에 맞는 값 삭제 - std::erase_if(vec, [](int n) {return n% 2 != 0; });
		직접 만든 함수도 사용 가능 std::erase_if(vec, is_odd);
bool is_odd(int n) {return n% 2 != 0;}

■ 람다 함수(lambda function)
C++11에서 도입된 이름이 없는 함수 객체를 만들 수 있게 되었다.

▶ [capture list] (받는 인자) -> 리턴 타입 {함수 본체}

• 리턴 타입을 생략한다면 컴파일러가 알아서 함수 본체에서 return 문을 보고 리턴 타입을 추측해준다.
(만약에 return 경로가 여러군데여서 추측할 수 없다면 컴파일 오류가 발생한다.)

[] (int i)->bool{return 1%2==1;}

▶[capture list] (받는 인자) {함수 본체}
리턴 타입을 생략할 경우 더 간단히 쓸 수 있다.

[](int i) {return i% 2==1;}

• 람다 함수는 바로 호출할 수 있다.
[](int i) {return i%2 ==1;} (3)	//true

• 람다 함수로 함수 객체를 생성한 후에 호출할 수도 있다.
auto func = [](int i) {return i%2 ==1; };
func(4);	//false

▶ 캡쳐 목록
람다 함수도 함수이기 때문에 자기 자신만의 스코프를 가진다. 일반적인 상황이라면 함수 외부에서 정의된 변수들을 사용할 수 없다.
• 하지만 람다 함수의 경우 캡쳐 목록(capture list)을 사용하여 변수에 접근할 수 있다.

int num = 0;
[&num] (int i) { 생략 }
이 경우에 레퍼런스를 캡쳐했다. 함수의 내부에서 num의 값을 바꿀 수 있게 된다.

[num] (int i) { 생략 }
&를 앞에 붙이지 않는다면 num의 복사본을 얻게 되는데, 복사본의 형태는 const이다.
(람다의 operator()가 기본적으로 const이므로 함수 내부에서 복사본을 수정할 수 없음. const 멤버 함수에서도 참조가 가리키는 원본 객체는 수정할 수 있어서 전자가 가능함.)
[num](int i) mutable {num=20;} 은 가능 //원본 num은 변경 안됨

▶ 클래스 멤버 함수 안에서 람다 사용할 때 멤버 변수 참조
멤버 변수num을 앞선 방법처럼 [&num]으로만 하면 컴파일되지 않는다.
num은 객체에 종속되어 있는 멤버변수이고, 람다함수는 이 num이 일반 변수라고 생각하기 때문이다.
이를 해결하기 위해 직접 멤버 변수 전달이 아닌 this를 전달해줘야한다.

[this] (int i) { this->num.. 생략 }

• this를 복사본으로 전달해서 함수 안에서 this를 이용하여 멤버 변수를 참조한다.
(참고로 this는 레퍼런스로 전달할 수 없다.)

▶ 캡쳐 리스트의 사용 방법
[ ] : 아무것도 캡쳐 안함
[&a, b] : a는 레퍼런스 캡쳐, b는 변경 불가능한 복사본으로 캡쳐
[&] : 외부의 모든 변수들을 레퍼런스로 캡쳐
[=] : 외부의 모든 변수들을 복사본으로 캡쳐

■ 원소 수정하기 (transform)

c transform (시작 반복자, 끝 반복자, 결과를 저장할 컨테이너의 시작 반복자, Pred)

transform(vec.begin(), vec.end(), vec.begin(), [](int i) {return i+1;});
vec의 begin부터 end까지 각 원소에 1를 더한 값을 vec.begin()부터 저장하게 된다.

• 값을 저장하는 컨테이너의 크기가 원래의 컨테이너보다 최소한 같거나 커야 된다.
(안 그러면 오류 발생)

transform 함수를 이용하면 for문을 쓸 필요도 없어지고, 내가 이 코드에서 무슨 일을 하는지 더 간단 명료하게 나타낼 수 있다.

■ 원소를 탐색하는 함수(find, find_if, any_of, all_of 등)

■ find 함수
template <class InputIT, class T>
InputIt find(InputIT first, InputIT last, const T& value)

▶ first부터 last까지 순회하면서 value와 같은 원소가 있는지 확인하고 있으면 이를 가리키는 반복자를 리턴한다.

auro result = std::find(vec.begin(), vec.end(), 3);
std::cout << "3은 " << std::distance(vec.begin(), result) +1 <<" 번째 원소";

반복자에 따라서 forward_iterator 라면 앞에서부터 찾고,
reverse_iterator 이면 뒤에서 부터 거꾸로 찾게 된다.
컨테이너에 중복되는 값이 있더라도 가장 먼저 찾은 것을 리턴한다.

모든 3 찾기
auto current = vec.begin();
while (true) {
	current = std::find(current, vec.end(), 3);
	if (current == vec.end()) break;
	std::cout << "3 은" << std::distance(vec.begin(), current) + 1 << " 번째원소" << std::endl;
	current++;
}

▶ 컨테이너에서 기본적으로 find 함수를 지원한다면 이를 사용하는 것이 훨씬 빠르다.
알고리즘 라이브러리에서의 find 함수는 그 컨테이너가 어떠한 구조를 가지고 있는지에 대한 정보가 하나도 없기 때문이다.

set의 경우 set에서 사용하는 find 함수는 O(logN)으로 수행 될 수 있다. (셋 내부 원소들이 정렬됨)
unordered_set의 경우 find 함수가 O(1)로 수행될 수 있다. (내부에서 자체적으로 해시 테이블을 이용하여 원소들을 빠르게 탐색해 나갈 수 있다.)

하지만 그냥 알고리즘 라이브러리의 find 함수의 경우 이러한 추가 정보가 있는 것을 하나도 모른채 처음부터 하나씩 확인해 나가므로 O(N)으로 처리된다.

벡터처럼 기본적으로 find 함수를 지원하지 않는 컨테이너에 사용하자.

■ find_if 함수
find_if 함수는 함수 객체를 인자로 받아서 그 결과가 참인 원소들을 찾게 된다.

auto current = vec.begin();
current = std::find_if(current, vec.end(), [](int i) {return i%3 == 2;});

■ any_of, all_of
any_of : 인자로 받은 범위안의 모든 원소들 중에서 조건을 하나라도 충족하는 것이 있다면 true를 리턴
all_of : 모든 원소들이 전부 조건을 충족해야 true를 리턴

std::all_of(users.begin(), user.end(), [](User& user) {return user.level >= 15; });
모든 유저들의 레벨이 15이상이어야 true리턴

■ C++ 문자열 (string과 string_view)

■ basic_string
std::string은 사실 basic_string 이라는 클래스 템플릿의 인스턴스화 버전이다.

template <class CharT, class Traits = std::char_traits<CharT>, class Allocator = std::allocator<CharT>>
class basic_string;

▶ basic_string은 CharT타입의 객체들을 메모리에 연속적으로 저장하고, 여러가지 문자열 연산들을 지원해주는 클래스다.
CharT 자리에 char 가 오면 std::string이 된다.

5가지 종류의 인스턴스화된 문자열
• std::string		std::basic_string<char>
• std::wstring	std::basic_string<wchar_t>	wchar_t의 크기는 시스템 마다 다르다. 윈도우에서 2바이트/유닉스 시스템에서 4바이트
• std::u8string	std::basic_string<char8_t>	C++20에 새로 추가 되었다. char8_t는 1바이트. UTF-8 문자열을 보관할 수 있다.
• std:: u16string	std::basic_string<char16_t>	char16_t는 2바이트. UTF-16 문자열을 보관할 수 있다.
• std::u32string	std::basic_string<char32_t>	char32_t는 4바이트. UTF-32 문자열을 보관할 수 있다.

▶ Traits는 주어진 CharT 문자들에 대해 기본적인 문자열 연산들을 정의해놓은 클래스다. (문자열의 대소 비교, 문자열 길이 재는 것 등등)
basic_string에 정의된 문자열 연산들은 전부다 Traits의 기본적인 문자열 연산들을 가지고 정의되어 있다.

basic_string : 문자열을 어떻게 보관하는지에 대한 로직
Traits : 문자열들을 어떻게 연산하는지에 대한 로직
으로 분리시킬 수 있다.

▶ 숫자들의 순위가 알파벳보다 낮은 문자열
아스키 테이블에서 숫자들의 값이 알파벳보다 작아서 더 앞에 오게 되는데, 숫자가 다른 문자보다 우선순위를 낮게 만들 수 있다.
basic_string의 Traits에 char_traits가 제공하는 모든 멤버 함수들이 구현된 클래스가 전달되어야 한다. (꼭 char_traits를 상속 받을 필요가 없다.)
가장 편하게 만드는 방법 : char_traits 상속 받은 후, 필요한 부분만 새로 구현

char_traits 에 정의되어 있는 함수들은 모두 static 함수들이다.
Tratis는 문자와 문자열들 간에 간단한 연산을 제공해주는 클래스이므로 굳이 데이터를 저장할 필요가 없기 때문이다. (이를 보통 Stateless 라고 한다.)
char_traits<char>에서 바꿔줘야 할 부분은 대소 비교하는 부분이다.
간단히 Traits만 바꿔주는 것으로 커스터마이징 된 basic_string을 사용할 수 있다.

■ 짧은 문자열 최적화 (SSO)
▶ 짧은 길이 문자열의 경우 따로 문자 데이터를 위한 메모리를 할당하는 대신에 그냥 객체 자체에 저장해버린다.
SSO - short string optimization

basic_string이 저장하는 문자열의 길이는 천차 만별이다.
때론 한 두 문자 정도의 짧은 문자열을 저장할 때도 있고, 수십만 바이트의 거대한 문자열을 저장할 때도 있다.
거대한 문자열은 드물게 저장되지만, 짧은 문자열은 굉장히 많이 생성되고 소멸되는데,
매번 모든 문자열을 동적으로 메모리를 할당 받는다면 길이가 짧은 문자열은 매번 메모리 할당이 이루어져야 한다. = 비효율적
(메모리를 할당하는 작업은 시간을 꽤나 잡아먹는다.)

그래서 나온게 SSO다.

// 이와같이 new 를 전역함수로 정의하면 모든 new 연산자를 오버로딩 해버린다.
// (어떤 클래스의 멤버 함수로 정의하면 해당 클래스의 new 만 오버로딩 됨)
void* operator new(std::size_t count) {
std::cout << count << " bytes 할당" << std::endl;
return malloc(count);
}

std::string s = "short";

• 클래스 외부의 함수로 new를 정의하게 된다면 모든 new 연산자들이 그 함수를 사용하게 된다.
반면에 클래스 내에 멤버 함수로 new를 정의하게 된다면, 해당 객체를 new로 생성할 때 해당 new 함수가 호출된다.

operator new를 정의하여 문자열 생성 시에 메모리 할당이 일어나는지 아닌지 관찰할 수 있다.

• C++11 이전의 basic_string 구현에서는 Copy On Write 라는 기법도 사용되었다.
문자열을 복사할 때, 바로 복사하는 것이 아닌, 복사된 문자열이 바뀔 때 비로소 복사를 수행하는 방식이다. C++11에서 개정된 표준에 따라 불가능해짐.

■ 문자열 리터럴 정의하기
C 스타일 문자열 리터럴
const char& s = "hello";
char s[] = "hello";

C++에서
auto str = "hello";
하면 string으로 정의되는 게 아닌, C와 마찬가지로 consr char* 로 정의된다.

■ 리터럴 연산자
리터럴 연산자(literal operator)는 C++14에 추가되었다.

auto str = "hello"s;
• 위와 같이 " "뒤에 s를 붙여주면 auto가 string으로 추론된다.

std::string operator"" s(const char *str, std::size_t len);	//리터럴 연산자 정의
"hello"s는 컴파일 과정에서 operator""s("hello", 5); 로 바뀌게 된다.

• 리터럴 연산자를 사용하기 위해 std::string_literals 네임스페이스를 사용해야 한다.

문자열 뿐만 아니라 정수, 부동 소수점 리터럴도 사용 가능하다.

이전에는 \를 입력하기 위해 \\와 같이 써야 했고 "를 입력하려면 \"로 입력해야했다.
근데 위 경우에는 고대로 쓰면 된다!

- 문제점 : 괄호 )"를 문자열안에 넣을 수 없다. 구분 문자를 추가하면 해결할 수 있다.
R"foo( )"; <-- 무시됨 )foo";
==> 컴파일하면 )"; <-- 무시됨 로 나온다.

▶ Raw string 문법 : R"/* delimiter */ ( /* 문자열 */ ) /* delimiter */"
delimiter 자리에 아무것도 없어도 되고, 원하는 문자열이 와도 되지만, 앞뒤delimiter끼리 같아야한다.

■ C++에서 한글 다루기
처음에 컴퓨터가 만들어졌을 때, 대부분 영미권 국가에서 사용했기에 문자를 표현하는데 1바이트 (=255개)로 충분하였다. 점차 전세계적으로 사용 확대되면서 세계 각국의 문자를 나타내는데에 한계가 나타남.

그래서 등장한게 유니코드(Unicode)다. 유니코드는 모든 문자들에 고유의 값을 부여한다. (아스키 테이블과 호환을 위해 기존의 숫자나 알파벳 등은 그대로다.)

문자 하나를 한 개의 자료형에 보관하기 위해 최소 int를 사용해야한다.
하지만 모든 문자들을 4바이트씩 지정해서 표현하는 것은 매우 비효율적이다. (영어의 경우 1바이트만 사용해도 전부 표현 가능함)

그래서 등장하는 것이 인코딩(Encoding)이다.
인코딩방식에 따라 컴퓨터에서 문자를 표현하기 위해 4바이트를 사용하는 대신, 어떤 문자는 1바이트, 어떤건 2바이트 등의 길이로 저장하게 된다. 

유니코드가 지원하는 3가지 형식의 인코딩 방식
• UTF-8 : 문자를 최소1 ~ 최대 4바이트로 표현한다. (문자마다 길이가 다르다.)
• UTF-16 : 문자를 2 혹은 4바이트로 표현한다.
• UTF-32 : 문자를 4바이트로 표현한다.

▶ UTF-32
UTF-32의 경우 모든 문자들을 4바이트로 할당하기 때문에 다루기가 매우 간단하다.
(문자열의 원소 개수와 실제 문자열의 크기가 일치한다.)
std::u32string s = U"이건 UTF-32 문자열";
u32string은 C++에서 UTF-32로 인코딩 된 문자열을 보관하는 타입이다.
" " 앞에 붙은 U는 해당 문자열 리터럴이 UTF-32로 인코딩하라는 의미다.

▶ UTF-8
UTF-32 방식은 모든 문자에 4바이트씩 할당하기에 비효율적이며, 자주 사용되는 인코딩 방식이 아니다.
웹상에서 많이 사용되는 인코딩 방식이 UTF-8이다.

std::string str = u8"이건UTF-8 문자열입니다";
str.size();	//32
한글 8개 x(3바이트) + 나머지 8개x(1바이트) = 32

" " 앞에 u8 써주면 된다.
그리고 대부분의 시스템의 파일이 UTF-8 형식일 것이기에 u8을 안 붙여도 알아서 UTF-8문자열이 될 것이다.

문자열 길이는 16이지만 출력은 32가 나왔다. UTF-8 인코딩 방식이 문자들에 최소 1 바이트 부터 최대 4바이트까지 지정하기 때문이다.
어떤 문자는 char 1개로 충분하고, 어떤 char 원소는 2, 3, 4개 까지 필요하게 된다.

std::string은 문자열이 어떤 인코딩으로 이루어져 있는지 관심이 없고, char의 나열로 이루어져 있다고 생각한다. 따라서 str.size() 했을 때 문자열의 실제 길이가 아니라 char가 몇 개있는지 알려준다.

문제는 string 단에서 각각의 문자를 구분 못한다. str[1] 하면 건이 나와야하는데 이상한 결과가 나온다. 출력된 것은 UTF-8 인코딩의 두번째 바이트다.

size()를 제외한 다른 모든 연산들은 문자열의 인코딩 방식과 무관하다.
특히 영문자와 섞여있는 경우 알파벳은 1바이트지만 한글은 3바이트로 해석되기 때문에 반복자를 통해 문자들을 순차적으로 뽑아내기 힘들다.

▶ UTF-16 인코딩
최소 단위가 2바이트다.
UTF-16으로 인코딩 된 문자열을 저장하는 클래스인 u16string도 원소 타입이 2바이트(char16_t)이다.

UTF-16 인코딩 방식은 대부분의 문자들이 2바이트로 인코딩된다. (알파벳, 한글, 한자)
물론 이모지나 이집트 상형문자 같은 건 유니코드 상에 높은 번호로 매핑되어 있는애들은 4바이트로 인코딩된다.

한글의 초성만 분리해내는 코드도 작성할 수 있다.
UTF-16도 때론 4바이트로 문자를 인코딩해야하기에 str[i]처럼 접근할 수 없다. 

가장 편한 방법은 어떤 문자열이든 UTF-32 인코딩으로 바꾸면 되지만, 메모리 사용량을 매우 증가시킨다.
다행히 UTF8-CPP 라는 C++에서 여러 방식으로 인코딩 된 문자열을 쉽게 다룰 수 있게 도와주는 라이브러리가 있다. (표준 라이브러리는 아니다.)

■ string_view
#include <string>		std::string_view

C++17. 문자열을 읽기만 하는 클래스다. (문자열을 소유하지 않는다.)
어딘가 존재하는 문자열을 참조해서 읽기만 하기에 string_view가 현재 보고 있는 문자열이 소멸된다면 정의되지 않는 작업(Undefined behavior)이 발생하게 된다.

bool contains_hi(std::string_view str)
{ return str.find("very") != std::string_view::npos; }

contains_hi("hi hello !!");
std::string s = "hmmm";
std::string_view sv = s;
sv.substr(0,3);

* string_view는 문자열을 소유하지 않기에 현재 읽고 있는 문자열이 소멸되지 않은 상태인지 주의해야 한다. *

• 메모리 할당 불필요, 문자열의 시작 주소값만 복사
• string_view에서 제공하는 연산들도 원본 문자열을 수정하지 않는 연산들이다. (find, substr(부분 문자열 얻는 함수) )
특히 string의 경우 substr이 실제 부분 문자열을 새로 생성해야하기에 O(n)으로 수행되지만, string_view의 경우 substr로 또 다른 view를 생성하므로 O(1)로 매우 빠르게 수행된다.
